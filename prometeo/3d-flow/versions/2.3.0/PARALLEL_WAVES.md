# PROTOCOLO DE PARALELISMO DE TANDAS · W4
No introducir un límite arbitrario de 10 chats ni esperar una tanda completa. El usuario puede lanzar 1, 10, 30, 50 o más trabajos simultáneos según su cuenta y recursos externos reales. Tres series numeradas INTEGRADORES/PERSONAJES/VIDEOJUEGOS; cada tarea ocupa un chat y no comparte estado editable con otros trabajos. Un chat recibe una URL numerada, lee manifest + brief exacto + método fijado, y produce la obra.

Los límites que sí importan son **de escritura**, no de cantidad de conversaciones:
- Rama privada única, nombre de proyecto y versión únicos; nunca reescribir otras ramas.
- Publicación bajo path aislado, nunca borrar archivos públicos de otro chat. Rebasing/CAS sobre último HEAD si otro publica mientras tanto.
- No cambiar FLOW_INDEX ni la versión del método desde un chat productor.
- No mutar manifiesto de lanzamiento para simular un estado en vivo.
- No obligar a completar una serie antes de lanzar otra. No suponer coordinación automática entre chats.
- Documentos de cada autoría en repo privado y URL pública candidato cuando se pueda, con estado honesto.
